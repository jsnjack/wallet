Live flight info on boarding passes

Gate, terminal, delays and status on a boarding pass, the way Google Wallet and Samsung Wallet show them. Researched 2026-11-19 from the providers' own pricing and API pages; prices and free tiers change, so the numbers are checked again at sign-up.

Decided 2026-11-19

Built with AeroDataBox on RapidAPI's free Basic plan. The key is pasted into Settings and kept with the app's settings, so the phone's Google backup carries it. (It first synced through Drive; Drive sync was removed the same day in favour of Google backup.) The .pkpass extras and Schiphol's API are not built.

Recommendation

Look flights up in AeroDataBox on RapidAPI's free Basic plan, with a key you create and paste into Settings. It needs no card, covers every airport on a trip, returns gate, terminal, belt, revised times and status in one call, and its pricing page names "a mobile application displaying flight number, time, status and gate" as an allowed use. The free plan allows about 200 lookups a month, which covers about 14 flights at the schedule below.

How Google and Samsung do it

Neither works it out on the phone. An airline that issues its pass through Google Wallet or Samsung Wallet pushes gate and time changes to the pass on their servers, and Google also matches flights against its own flight-status data. Apple Wallet passes (.pkpass) carry an update address that the airline's server answers with a newer pass; since iOS 26, Apple Wallet also fetches flight status itself. This app has no airline partnership and no server, so it asks a flight-status service directly from the phone.

  • Code screen: gate, terminal, departure time and a status pill above the code; a delay shows the old time beside the new one.
  • Up next and the "today" notification: "Gate D7 · 14:35", updated in place; a gate change or a delay of 15 minutes or more also alerts you.
  • The pass's time: the barcode has only the date, so the first lookup fills in the scheduled departure time. Up next then starts 24 hours before departure instead of the whole day before.
  • After landing: arrival gate and baggage belt, when the service has them.

When the app asks

One lookup serves every passenger on the flight, because they share one tile.

That is about 12–15 lookups per flight. Doze can delay background lookups by some minutes, as it already does for reminders.

Privacy and setup

  • The app sends only the airline, flight number and date with your key; never names, booking references or barcodes.
  • The key is stored with the app's settings, so Android backup and phone transfer carry it. A key built into the APK was ruled out: anyone with the APK could read it, and F-Droid builds would not have it.
  • Setup: create a RapidAPI account, subscribe to AeroDataBox's free Basic plan, copy the key into Settings → Live flight info. With no key, nothing changes.
  • The app's internet use is no longer "Drive only"; AGENTS.md records the new service.

Free extras from .pkpass files

These need no key, but only help passes imported as .pkpass files, not screenshots.

  • Gate and boarding time already in the pass. Airline passes built for iOS 26 can carry departureGate, departureTerminal and originalBoardingDate; the importer could read them. Cheap to add.
  • The airline's own updates. A pass with an update address can be asked for its newest version with the token inside it. Apple's documentation says no device registration is needed for that request, but it is untested against a real airline, and there is no public evidence that KLM passes include the address.
